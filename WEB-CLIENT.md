# EqyCord Web

The portable Windows developer package uses the installed official Brave browser with a separate profile in `%LOCALAPPDATA%/EqyCord/WebProfile`. It loads the included EqyCord extension and opens Discord Web in an app window. It does not replace an existing Brave profile or copy credentials, Canary settings or OAuth sessions. Sign in to Discord yourself on first use. Keep the complete extracted package together and launch `EqyCord-Web.cmd`; the launcher is required each time because the development extension is loaded at startup.

FreezeCam, FakeLagVoice and VoiceTroll are enabled by default on a fresh web installation so their outgoing WebRTC capture hooks run before a call. Their effects start OFF. Existing choices to disable plugins remain respected. Each plugin can be disabled independently in Settings → Plugins. The three compact controls are camera/pause, broken waveform and robot; a red slash indicates OFF. Join a browser voice call and enable the camera before testing FreezeCam. Click an effect control only after an outgoing track is available. If plugins were enabled after capture began, leave and rejoin the call.

Voice effects are applied before lag effects. Only locally captured microphone and webcam tracks are processed; incoming media and screen sharing are excluded. Camera-off and microphone mute remain respected. The outgoing engine has real two-peer browser receiver tests, but a Discord voice call with a second account remains a required compatibility test. This package does not add support to native Canary's compiled media engine.

Browser and Canary preferences are separate. Import a settings backup through EqyCord Backup & Restore if desired, then verify plugin choices and reload Discord Web before joining a call. CustomProfile sharing requires its own Connect Discord account action in the web client. Profile colors are a cosmetic profile projection and do not grant Nitro account privileges.

This is an unpacked developer extension, not a browser-store release. To use another compatible browser, load the `extension` directory through its supported unpacked-extension workflow. Never disable browser or endpoint protections. Automatic extension release updates are not configured. Build commands are `pnpm buildWeb` and `scripts/eqycord/web/package.ps1`; the matching source and original GPL-3.0-or-later license are included.

Web audio graph correction: locally captured microphone inputs are now processed before an application Web Audio graph, so a derived destination track retains voice and lag effects. A direct-track test and a downstream-graph test both measure audio at a real remote WebRTC receiver, including mute and dry restoration after disabling plugins. The old engine fails the graph regression with "Web Audio capture was not detected". A dry bridge remains alive until the original capture ends when an existing downstream graph still consumes it. This is not proof of compatibility with a live Discord call; that check remains required. Browser warnings now describe missing capture without incorrectly identifying the browser as Canary.

Strong initial settings: FakeLagVoice uses Extreme (intensity 1, frequency 3, duration 0.2); VoiceTroll uses intensity 1, echo 0.8 and distortion 1. A one-time settings migration applies these values without deleting presets; subsequent customizations are preserved. Effects remain OFF at startup. Ghost is now enabled by default on fresh profiles; an existing saved OFF setting still needs enabling in Plugins. All four user-area controls use compact widths. User reports confirmed audible VoiceTroll and Extreme FakeLagVoice effects plus stop behavior on Discord Web; native Canary effects remain unsupported.
